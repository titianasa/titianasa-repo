# ADR-0006: RBAC (Role-Based Access Control)
Status: Accepted
Date: 2026-08-22
Supersedes: -
Superseded by: -

## Context
Multi-tenant (organization) + multi-role per user (ADR-0001) butuh permission matrix eksplisit sebelum endpoint apapun ditulis, supaya authorization check konsisten di semua handler, bukan ditambal belakangan.

## Decision

### Role final untuk MVP (di `user_organization_roles.role`)
```
platform_admin        -- akses lintas organization, hanya untuk internal ALR
org_owner              -- pemilik organization (sekolah/tutor org)
academic_director      -- kelola curriculum & academic policy 1 org
curriculum_developer    -- buat/edit content, tidak bisa publish langsung
reviewer                -- approve/reject content sebelum publish
teacher                 -- kelola kelas, nilai, attendance
tutor                   -- sama seperti teacher tapi di konteks marketplace (private/group course)
student                 -- learner
parent                  -- lihat progress anak (read-only + restricted)
```

### Permission matrix (ringkas, per resource utama)

| Resource / Action | platform_admin | org_owner | academic_director | curriculum_dev | reviewer | teacher/tutor | student | parent |
|---|---|---|---|---|---|---|---|---|
| Curriculum: create/edit | ✅ | ✅ | ✅ | ✅ (draft only) | ❌ | ❌ | ❌ | ❌ |
| Curriculum: publish | ✅ | ✅ | ✅ | ❌ | ✅ | ❌ | ❌ | ❌ |
| Question bank: create/edit | ✅ | ✅ | ✅ | ✅ (draft only) | ❌ | ❌ | ❌ | ❌ |
| Question bank: publish | ✅ | ✅ | ✅ | ❌ | ✅ | ❌ | ❌ | ❌ |
| Class: create/manage | ✅ | ✅ | ✅ | ❌ | ❌ | ✅ (kelas sendiri) | ❌ | ❌ |
| Attempt: submit | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ✅ (milik sendiri) | ❌ |
| Evaluation (human): create | ✅ | ✅ | ✅ | ❌ | ❌ | ✅ (siswa sendiri) | ❌ | ❌ |
| Mastery/Progress: view | ✅ (semua) | ✅ (org) | ✅ (org) | ❌ | ❌ | ✅ (siswa sendiri) | ✅ (milik sendiri) | ✅ (anak sendiri, read-only) |
| Credit/Transaction: view | ✅ (semua) | ✅ (org, agregat) | ❌ | ❌ | ❌ | ✅ (milik sendiri) | ✅ (milik sendiri) | ❌ |
| Proctoring event: review | ✅ | ✅ | ✅ | ❌ | ❌ | ✅ (kelas sendiri) | ❌ | ❌ |
| Organization settings | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |

Aturan umum di luar tabel:
- **Scoping selalu by organization_id** kecuali `platform_admin`. Setiap query list wajib difilter `organization_id` dari JWT claim, bukan dari parameter request (mencegah IDOR).
- **"Milik sendiri"** diartikan `resource.user_id == auth.user_id` — dicek di service layer, bukan cuma di frontend.
- `parent` selalu read-only dan hanya untuk child account yang terhubung eksplisit lewat tabel relasi (belum dirinci di MVP awal — ticket terpisah kalau fitur Kids/Parent mode digarap).

### Implementasi teknis
- Middleware Axum: extract JWT → resolve `user_organization_roles` aktif (dari header `X-Organization-Id` atau default org user) → inject `AuthContext { user_id, organization_id, role }` ke request extension.
- Setiap handler yang butuh authorization memanggil helper `require_permission(ctx, resource, action)` — daftar permission didefinisikan sebagai const map (bukan if-else bertumpuk di tiap handler), supaya matrix di atas dan kode tidak divergen.

## Alternatives considered
- **Permission per-endpoint hardcoded di tiap handler** — ditolak, riskan drift dari matrix ini dan susah diaudit.
- **Role tunggal per user (bukan per organization)** — ditolak, bertentangan dengan requirement multi-role lintas organization di ADR-0001.

## Consequences
- (+) Satu tabel rujukan matrix ini + const map di kode — audit permission tinggal bandingkan dua tempat itu.
- (−) Matrix ini akan tumbuh drastis begitu resource baru masuk (marketplace, certificate, dll) — perlu di-review ulang sebagai ADR baru saat Phase 7/8 dimulai, jangan menambal diam-diam di kode.
