## Keputusan scope (baca duluan)

Sesi ini membalik keputusan eksplisit sesi sebelumnya ("hapus Rust, full Bun") — user secara sadar dan eksplisit memilih untuk migrasi kembali ke Rust, kali ini dengan Axum (bukan Actix-web yang disebut user awalnya — dikonfirmasi lewat `Cargo.toml` proyek referensi bahwa itu sebenarnya Axum) + SQLx, meniru arsitektur proyek `/home/john/Dev/parelabs-workspace/parelabs-backend/api` (proyek terpisah, tidak berhubungan dengan Titian Asa, dipakai murni sebagai referensi pola/konvensi Rust yang sudah terbukti jalan).

**Strategi: rewrite penuh dulu, baru cutover** (bukan migrasi bertahap per-route ke production) — `titian-backend-bun` tetap jalan tanpa disentuh sampai `titian-backend-rust` benar-benar siap menggantikan semuanya. Proyek baru ada di `titian-backend-rust/`, sibling dari `titian-backend-bun/`, jalan standalone di port `8090` (Bun tetap di `8081`).

**Kontrak wire HARUS sama persis** — `titian-web` tidak berubah sama sekali sampai cutover asli terjadi (R12). Bentuk JSON error (`{"error": "code", "detail": ...}`), semua field response, semua route path/method harus identik dengan yang `titian-backend-bun` hasilkan sekarang. Ini bukan kesempatan untuk "sekalian dirapikan" — tugasnya port, bukan redesign.

**Pola arsitektur** (dari riset langsung ke `parelabs-backend/api/src`, bukan tebakan):
- Layout: `handlers/`, `routes/`, `services/`, `models/{requests,responses}`, `middleware/`, `db/`, `observability/` + `config.rs`, `errors.rs`, `main.rs`(tipis, cuma bootstrap)/`lib.rs`(semua `pub mod`, supaya `tests/` bisa akses), `state.rs`.
- `AppState` — struct polos (bukan `Clone`), selalu dibungkus `Arc`, isinya `db: PgPool`, `config: Config`, plus trait-object/struct untuk tiap integrasi eksternal (di R1: `google_verifier`; nanti R8: AI provider trait, Meet provider trait; R9: storage trait) — DI persis pola `buildApp({db, config, aiProvider, ...})` yang sudah ada di test helper Bun.
- **Tidak ada layer `repository/` terpisah** — beda dari `titian-backend-bun`. Query SQLx langsung di `services/*.rs` (fungsi async lepas, bukan struct/trait), sama seperti `parelabs-backend/api/src/services/auth.rs`.
- SQLx: makro compile-time (`query!`/`query_as!`) sebagai default — sudah dikonfirmasi jalan langsung ke schema asli `titian_bun` yang sama dipakai Bun (lihat catatan migrasi di bawah). Baru pakai `query_as::<_, T>()` runtime kalau query-nya genuinely dinamis.
- Error: `AppError` enum + `thiserror` + `impl IntoResponse`, TAPI bentuk body JSON ikut `titian-backend-bun/src/error.ts` (`{"error", "detail"}`), BUKAN bentuk `{"error":{"code","message"}}` punya parelabs.
- Test: `#[sqlx::test]` = padanan langsung `tests/helpers/db.ts`'s `withTx()` (DB transaksional asli, di-rollback otomatis) — TAPI beda dari Bun: `#[sqlx::test]` bikin database test BARU (kosong, auto-migrated dari `./migrations`, auto-dibuang setelah test) per test run, bukan transaksi di atas DB dev yang sama. Test HTTP level lewat `routes::create_router(state)` + `tower::ServiceExt::oneshot`, DI verifier/provider di-seed langsung (contoh: `GoogleTokenVerifier::with_seeded_key(...)`, lihat `tests/auth_test.rs`).

**Catatan migrasi DB (PENTING, jangan diulang lagi kalau lupa)**: 25 file SQL migrasi `titian-backend-bun/migrations/*.sql` disalin apa adanya ke `titian-backend-rust/migrations/` (isinya sudah plain SQL, tidak perlu diubah). Karena `titian_bun` (database dev yang sama dipakai Bun) sudah punya semua tabel dari migrasi Drizzle-nya sendiri, TAPI sqlx punya tabel bookkeeping-nya sendiri (`_sqlx_migrations`) yang awalnya kosong — kalau dibiarkan, `sqlx::migrate!().run()` akan mencoba re-run SEMUA 25 file dari awal, gagal di file pertama yang bentrok ("already exists"), dan (ini bug yang sempat kejadian) **BERHENTI TOTAL di situ tanpa pernah mencoba file-file berikutnya** — bukan skip-per-file. Fix yang dipakai (sudah diverifikasi jalan): bikin database Postgres kosong sementara, jalankan migrate di situ (semua 25 file jalan bersih dari nol, sqlx hitung checksum yang benar), `pg_dump --data-only` tabel `_sqlx_migrations`-nya, lalu `INSERT` baris-baris itu (dengan checksum asli) ke `_sqlx_migrations` di database `titian_bun` yang sebenarnya. Setelah itu restart bersih, tidak ada warning sama sekali. Kalau nanti nambah migrasi baru buat R2 dst., itu akan otomatis ke-apply normal (checksum tidak match apa pun yang lama, jadi bukan "already exists").

`.env` proyek baru pakai `JWT_ACCESS_SECRET` dan `GOOGLE_CLIENT_ID` yang SAMA persis dengan `titian-backend-bun/.env` (disalin langsung, tidak pernah ditampilkan ke chat) — supaya token yang diterbitkan salah satu bisa diverifikasi rasional untuk dibandingkan saat testing manual, dan supaya login Google asli langsung jalan tanpa setup OAuth client baru.
