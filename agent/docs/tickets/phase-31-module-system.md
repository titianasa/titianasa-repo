## Keputusan scope (baca duluan)

Titian Asa berpindah dari "aplikasi belajar Bahasa Inggris" menjadi "asisten belajar seumur hidup dengan AI" — subjek apa pun, tidak lagi terkunci ke CEFR/grammar. Model konten saat ini (`curricula → levels → units → lessons → content_blocks`) kaku dan ber-flavour Bahasa Inggris (`curricula.framework CHECK IN ('cefr','cambridge',...)`), dan tidak bisa merepresentasikan "satu unit konten yang dipakai ulang di banyak jalur belajar" — kebutuhan mendasar katalog subjek generik.

User meminta 2 hal konkret, dievaluasi terhadap implementasi NYATA ParaLabs Workspace (proyek sibling, `/home/john/Dev/parelabs-workspace/`), bukan asumsi:

1. **Sistem modul/folder nested ala ParaLabs** — dikonfirmasi lewat riset schema langsung: `org_modules` ParaLabs adalah SATU tabel self-nesting (`parent_id` self-FK + `is_folder` boolean — "folder" cuma baris modul dengan flag itu), dipakai ulang lewat M2M ke banyak "Program" container, dengan urutan+prerequisite per-program. Tree KEDUA yang independen (`org_module_items.parent_id` + `node_type: section|item`, depth ≤5) menyusun konten DI DALAM satu modul. Drive Titian (assets/folders/resource_shares, sudah jalan sejak R9) sudah cover sistem file-manager terpisah ala ParaLabs — tidak perlu kerja baru di situ.
2. **Editor kolaboratif real-time**, "seperti Canva/Google Docs," format tersimpan tetap markdown rich. Koreksi yang muncul & diterima saat diskusi: editor ParaLabs sendiri (Tiptap) TERNYATA BUKAN multiplayer — tidak ada CRDT, tidak ada wiring WebSocket meski UI-nya mirip. WebSocket Canvas Titian sendiri (P26-001, feedback menulis tutor/siswa) juga dikonfirmasi BUKAN CRDT — last-write-wins overwrite string penuh, diam-diam menimpa edit bersamaan. Merging multi-user asli butuh CRDT sungguhan. Dikonfirmasi tersedia native di Rust: `yrs` (port CRDT Yjs) + `yrs-axum` (integrasi protokol sync WebSocket Axum) — tidak perlu runtime kedua (Node/Hocuspocus), konsisten dengan arsitektur all-Rust proyek ini.

Fakta kunci dari riset yang membentuk rencana ini (jangan diulang risetnya, sudah diverifikasi sesi ini):
- **Nol data kurikulum produksi ada di mana pun** di `titian-backend-rust` (tidak ada seed, tidak ada migrasi ber-INSERT) — penggantian schema bersih tanpa risiko migrasi data, cuma perlu update test fixture.
- Mesin learning-science Titian (`concepts`/`masteries`/`frss_schedule`/`questions`/`assessments`/`attempts`) SUDAH subject-agnostic di level schema — cuma layer authoring/organisasi di atasnya (curricula→lessons→content_blocks) yang dalam scope di sini. JANGAN sentuh wilayah ADR-0002/ADR-0003.
- UI authoring Studio penuh SUDAH ADA (`titian-web/src/app/studio/`), termasuk editor rich Tiptap/ProseMirror (`AlmEditor`) dengan konversi ALM-markdown↔ProseMirror dua arah yang sudah dibangun (`doc.ts`'s `blocksToDoc`/`docToAlm`). ​Ini UPGRADE infrastruktur yang sudah jalan, bukan bangun dari nol.
- **Batasan versi keras ditemukan & diselesaikan bareng user**: `yrs-axum` (kedua versi publikasinya, 0.8.1/0.8.2) butuh axum 0.8; proyek ini pakai axum 0.7. **Keputusan: upgrade seluruh backend ke axum 0.8 dulu**, sebagai milestone sendiri, bukan bikin adapter bypass manual. Axum 0.8 mengubah syntax path parameter dari `/foo/:id` jadi `/foo/{id}` (dikonfirmasi 92 kemunculan di `src/routes/*.rs`) — itu blast radius mekanis utamanya, plus companion bump `tower-http` 0.5→0.6.

"UI futuristik" adalah fase **terpisah, belakangan** — TIDAK dalam scope di sini.

Urutan milestone (dependency chain): `M0 → M1 → {M2, M3} → M4 → M5`. Setiap milestone independently shippable & testable — ini akan makan banyak sesi, jangan dipadatkan.

### P31-005 — Backend CRDT: real-time collaborative editing (M3)
**Status:** ✅ selesai dan teruji (2026-09-07)
**Depends on:** P31-001 (axum 0.8), P31-002 (tabel `module_items`)

**Deskripsi**: `Cargo.toml` — `yrs`, `yrs-axum`, `futures-util` baru. **Penemuan penting yang mengoreksi rencana asli**: rencana menyebut pin `yrs = "0.27"` + `y-sync = "0.4"` sebagai dependency terpisah, tapi verifikasi langsung ke `yrs-axum 0.8.2`'s Cargo.toml menunjukkan itu SALAH — `yrs-axum` sebenarnya pin `yrs = "0.18.2"` (bukan versi terbaru 0.27 yang ada di crates.io), dan protokol sync-nya (`Message`/`Protocol`/`Awareness`) sudah tersedia langsung dari `yrs::sync`, TIDAK butuh crate `y-sync` terpisah sama sekali. Menambahkan `yrs = "0.27"` sendiri di awal menghasilkan 3 versi `yrs` berbeda hidup berdampingan di dependency graph (0.17 dari `y-sync`, 0.18 dari `yrs-axum`, 0.27 dari deklarasi sendiri) — tipe `Awareness`/`Doc` dari versi berbeda TIDAK saling kompatibel di Rust meski nama sama, bikin `AwarenessRef` (`Arc<RwLock<yrs::sync::Awareness>>`) tidak pernah cocok. Fix: pin `yrs = "=0.18.8"` (exact match ke resolusi `yrs-axum`'s sendiri), hapus `y-sync` total. Migrasi baru `0027_module_items_yjs_state.sql` (`yjs_state bytea`, `yjs_state_updated_at timestamptz`, keduanya nullable).

`services/collab_hub.rs` — `CollabHub`: `HashMap<Uuid, Arc<Room>>` (bukan `Vec`/langsung `BroadcastGroup` — `Room` membungkus `AwarenessRef`+`BroadcastGroup`+subscriber counter+handle checkpoint task). `join()`: koneksi pertama untuk satu `item_id` memuat `yjs_state` tersimpan (kalau ada) ke `yrs::Doc` baru via `Update::decode_v1`+`apply_update` SEBELUM membuat `BroadcastGroup`, lalu spawn task interval checkpoint (`config.collab_checkpoint_interval_seconds`, default 15 detik). `leave()`: begitu subscriber terakhir keluar — checkpoint final, `abort()` task interval, HAPUS entry dari map (beda sengaja dari `CanvasHub` yang tidak pernah di-prune — alasannya `CanvasHub`'s doc comment sendiri bilang itu aman karena maksimal 2 partisipan per sesi; `module_items` bisa berjumlah ribuan seiring waktu, jadi wajib di-evict atau memori bocor).

`handlers/collab_ws.rs` — `GET /ws/module-items/{item_id}/collab?token=...`, auth mirror `canvas_ws.rs` persis (header `Authorization` sintetis dari query param, `resolve_auth_context`). Gate `Resource::ModuleItem, Action::Create` + tolak (close 1008) kalau `module_items.status` adalah `published`/`archived` (perluasan ADR-0008 ke socket collab — v1 cuma authoring, bukan live-viewing konten published). **Bug routing nyata ditemukan & diperbaiki**: rute WS ini awalnya ditaruh di `module::protected_routes()` — itu SALAH, karena router itu ada DI BELAKANG `auth_middleware` layer yang mewajibkan header `Authorization` asli; browser tidak bisa set custom header saat WS handshake, jadi request akan 401 sebelum pernah sampai ke handler.
